## A311D 底板 PD 前端背靠背仿真（用户在调）
- 场景：5/9/12V 代表 PD 档位，每次只开一档（互灌问题不存在）；底部 +5V/地代表 CH224K PG 驱动栅极；PMOS 背靠背共源。
- 12V 档仿真通过：输出 11.781V @1k（压降 0.22V，等效 Rds≈18Ω，仿真默认模型偏大）。
- 实锤问题（三档仿真已证实）：12V 档输出 11.781V（Δ0.219V）；9V 档 8.627V（Δ0.373V，Rds 翻倍）；5V 档输出仅 220µV 整路断电。结论：栅极固定 5V 的驱动方案只有 12V 档可用。
- **用户需求（关键）**：PD 9V/12V 导通向后级供电，5V 不供电。→ 驱动 FET 栅极必须用**VBUS 幅值阈值检测**（分压+比较器/电压监视器，阈值≈8V），不能用 CH224K PG（逻辑 power-good，不携带电压值）。
- **更正（用户指出）**：PG 经 1MΩ 上拉到 VBUS（非固定5V），栅极 0↔VIN 摆幅已实现（PG 拉低→导通，PG 释放→栅=VBUS→关断）。我此前"栅固定5V"的批评是误读，撤回。
- 用户确认：CH224K PG 在 5V 档不拉低（保持开漏高阻），仅在拿到 ≥9V 协商电压时拉低。→ PG+1M 上拉到 VBUS 的方案**已正确实现"9/12V 通、5V 断"**，无需额外 VBUS 阈值检测（加是冗余）。之前"PG 不可信需阈值检测"的担忧基于通用 PD 芯片假设，对 CH224K 不成立，已撤回。
- 结论：PD 前端诱骗成功判断电路 = 正确。栅极 0↔VIN 摆幅由 1M 上拉到 VBUS + PG 开漏拉低实现。
- 电压边界（用户确认）：协商链 12→9→5，板子 VBUS 封顶 12V，无 15/20V；CH224K PG 脚 abs max -0.5~13.5V，12V 工作点在规格内（余量仅1.5V）。建议 PG 脚并 12V 齐纳钳位做裕量保险。无需改高压驱动拓扑。

## PHY 选型结论（YT8531C vs RTL8211F）
- **是 p2p（pin-to-pin）器件，可互换**。YT8531C 是裕太微对 RTL8211F 的国产替代料（同 QFN48-6x6）。
- 差异（实测资料）：YT8531C 55nm / 功耗~420mW@1000M / 温度 -40~85℃；RTL8211F 65nm / ~450mW / 0~70℃。→ **YT8531 更优**。
- **DTS 影响（重要）**：YT8531 常需 `phy-mode = "rgmii-id"`（MAC+PHY 各给 ~2ns 延时），RTL8211F 一般用 `rgmii`。由 strap 电阻决定：RXD0/RXDLY 上拉→RX延时开；RXD1/TXDLY 下拉→TX延时关。本板 R62~R65/R75/R77/R79/R80 已配。
- **compatible 用 `ethernet-phy-ieee802.3-c22`**（通用 C22 绑定），不是厂商私有 compatible。
- mainline 已内置 **`CONFIG_MOTORCOMM_PHY`** 驱动 YT8531 系列，无需移植。`dmesg` 应显示 `driver [Motorcomm YT8531]`。
- 通用 PHY reset 新写法：`mdio { reset-gpios = <...>; reset-delay-us=...; reset-post-delay-us=...; }`，用标准 mdio.yaml 属性而非 `snps,reset-gpio`（后者已弃用）。

- ⚠ **GPIOA_2 复用 = `TDMB_FS`/`TDMB_SLV_FS`**（TDM 帧同步）。本板已用作 FUSB340 SEL；**若日后启用 TDM 音频会冲突**。
- **RGMII 与 RMII 完全互斥**（规格书 `PRG_ETH_REG1` 0xff634544 bit[0]）：
  - 1 = internal 001 = RGMII；0 = internal 100 = RMII
  - **"sampled only during reset assertion and ignored after that"** → 仅复位时采样，运行中无法切换
  - 本板 GMAC0 = RGMII（接 YT8531H），是唯一以太网口。**FPC6 的 4 线 MDI(TP/TN/RP/RN) 是差分，不是 RMII**，属另一路。
- **A311D MAC 侧可设 RGMII TX 延迟**：`PRG_ETH_REG1` bit[6:5] = 00(0)/01(¼≈2ns)/10(½≈4ns)/11(¾≈6ns) cycle。
  RGMII 规范要 2ns，MAC 侧与 PHY 侧**二选一不叠加**。Linux 下**用 `phy-mode` 而非直接写寄存器**：`rgmii`/`rgmii-id`/`rgmii-txid`/`rgmii-rxid`。本板建议 `rgmii-id`。
- **教训**：规格书 pad 表列出复用名 ≠ 启用该功能。用户口述信号名要先分清"SoC 硬件功能"还是"板级统一命名"。

## 第十二轮：参考对象选择 + R110 布局（设计阶段咨询）
**参考谁？**
- ✅ **Khadas VIM3 是首选**：同 SoC(A311D) + 同 PHY(RTL8211F)，mainline 有`meson-g12b-s922x-khadas-vim3.dts` 权威 DTS。
- ⚠ BananaPi M2S仅可参考 strap 接法，其 GMAC 延时特性与 A311D 不同。
- mainline 邮件列表（Andrew Lunn）：*"these boards that I am aware of are using an RTL8211F PHY which implements a 2ns PHY TX delay"* → VIM3 用 `phy-mode="rgmii-id"`。

**⚠⚠ 关键发现：RTL8211F 驱动会用软件寄存器覆盖 strap！**（`drivers/net/phy/realtek.c` `rtl8211f_config_init`）
| phy-mode | TX | RX |
|---|---|---|
| `rgmii` | 驱动**关掉**(0ns) | 驱动**关掉**(0ns) |
| `rgmii-txid` | 2ns | 0ns |
| `rgmii-rxid` | 0ns | 2ns |
| `rgmii-id` | 2ns | 2ns |
→ 所以本板 strap(TXDLY=1/RXDLY=0) 在 `rgmii` 下会被驱动**强制清零**，RX 侧 0ns，违反 RGMII 规范。
→ **建议设计阶段改为：RXDLY也上拉（贴 R75、拆 R74）+ `phy-mode="rgmii-id"`**，双向各 2ns，不依赖 PCB 走线补偿。（改动成本：一贴一拆）
→ 保持现状则必须用 `rgmii-txid` 且核对 RXC/RXD 走线长度差≈2ns。

**R110（Q8 基极限流电阻）布局：应靠近 Q8，不靠近核心板**
- 链路 `CN3-37 ── R110(100Ω) ── Q8.1(BASE)`。
- 理由：R110 在此**不是阻抗匹配电阻，而是基极限流+噪声抑制**。BE 结极敏感（µA 级干扰即可误导通）；若 R110 靠连接器侧，R110→BASE 段拾取噪声**绕过 R110 直灌基极**，滤波失效。靠近 Q8 可使噪声被衰减 ~1000 倍，且 R110→BASE 走线≤5mm 减小天线面积。
- ⚠ 区分规则：*"串联电阻靠驱动端"* 仅适用于**高速信号阻抗匹配**；低速 GPIO 控制诉求是**抗干扰**，故靠**负载端**。
- **⚠ 顺发现设计缺口**：`SYS_LED` 网络在下板侧**无任何上下拉**（仅 CN3.37 + R110.1）。GPIO Hi-Z 时（boot 早期/线缆未插/复位）基极悬空 → **运行灯随机闪烁**。建议下板加 **10kΩ 下拉**，或确认核心板侧已有偏置。
- **⚠ R110=100Ω 时基极电流≈26mA**((3.3-0.7)/100)，对多数 SoC GPIO（额定 8mA）偏大。LED 电流仅 ~0.3mA，β 要求低，**可考虑加大到 220Ω~470Ω**。

## 第十三轮：PCB 等长数据实锤 phy-mode（推翻前两轮结论，最终定案）
**新证据**：用户提供立创 EDA **等长网络组面板**（GMAC0_TX 6根 / PHY0_RX 6根）：
- TX 组：TXCLK 485.1 / TXD3 484.2 / TXEN 483.5 / TXD0 481.9 / TXD1 480.2 / TXD2 478.6 mil
- RX 组：RXCLK 755.9 / RXD1 755.9 / RXD3 755.9 / RXDV 755.9 / RXD0 751.8 / RXD2 748.6 mil

**换算结论**（FR4 ≈ 0.15ns/inch ≈ 0.00015ns/mil）：
- TX 组内散布 **6.5 mil ≈ 0.98 ps**；RX 组内散布 **7.3 mil ≈ 1.10 ps**
- clock 相对最长 data：TX 仅偏 **0.14 ps**，RX **0 ps**
- RGMII 需求 **2000 ps** → **PCB 只提供 0.007%**
- **2ns 若靠 PCB 走线需约 13000 mil**，与实际 500/750 mil 差一个数量级

**→ PCB 是标准「等长设计」，2ns 完全靠 PHY 内部延迟线提供（业界从不用 PCB 补偿 RGMII延时）。**

**✅✅ 最终定案：`phy-mode = "rgmii-id"`**
- `rgmii-id` 下mainline `rtl8211f_config_init()` 用软件寄存器**强制打开 TX+RX 双向 2ns**
- **无需改任何硬件**：strap（TXDLY/RXDLY 上下拉）只是上电默认值，驱动会覆盖
- ❌ **禁用 `rgmii`**：驱动会**关掉**PHY 两个延时 → 时序崩溃、千兆链路起不来
- ❌ 禁用 `rgmii-txid`/`rgmii-rxid`：只开单向，缺一边2ns
- 与 Khadas VIM3（同 A311D+RTL8211F）mainline DTS 配置一致

**⚠ 我前两轮的结论作废**：
1. 第十二轮说"RX 无延时违反规范，依赖 PCB 走线长度差补偿" → **错**，PCB 偏移≈0，等长设计本就该靠 PHY 延时
2. 第十二轮建议"贴 R75 改 RXDLY 上拉" → **多余**，`rgmii-id` 下驱动软件接管，strap 无关
3. 第十一轮的 `rgmii` → **错**，那会让驱动关掉延时

**教训**：RGMII 延时归属必须先看 **PCB 实测等长数据**，不能只看 strap 或凭经验推断。strap 在 `rgmii-id` 下会被驱动覆盖，不具决定性。
分析脚本：`rgmii_timing.py`（可复算）。

## 第二十二轮：FUSB340 SEL 悬空电平 + U-Boot 冷切换脚本
**FUSB340 规格书实证（onsemi FUSB340 Datasheet）**
- Pin 6 = `S`(SEL) Input，**Switch Select (0=SW1, 1=SW2)**；Pin 7 = `/OE`(OE) Input，**(0=Switches Enabled, 1=Switches Disabled)**
- Truth Table（VIM3 版）：`_EN=H` → TX/RX 全 Hi-Z；`_EN=L, S=L` → TX1/RX1(High)；`_EN=L, S=H` → TX2/RX2(Low)
- **Recommended Operating Conditions Note 3 原文**：*"The control inputs must be held HIGH or LOW; **they must not float**."*
- **SEL 无内部上下拉**（规格书未定义，仅标"1.8-V Compatible Logic Inputs"）→ 悬空电平不确定，**必须外部确定**。
- 参考：onsemi EVBUM2720/D 评估板用跳线：*"No shunt on SEL forces SEL=H (RX2/TX2); Shunt on SEL forces SEL=L (RX1/TX1)"* →印证二选一跳线做法。

**本板 R85/R87 二选一（网表实测）**
```
GPIOA_2 ──┬── R86(0Ω) ──→ U28.6(FUSB340 SEL)
          ├── R87(4.7k) ──→ A_3V3   (上拉)
          ├── R85(4.7k) ──→ GND     (下拉)
          └── R123(22Ω) ──→ FPC3.22
```
- 贴 R85 → LOW → USB3.0（默认）；贴 R87 → HIGH → PCIe。
- **两颗都贴** → 3.3V 经 4.7k//4.7k = 1.65V 未定义，**禁止**；**都不贴** → 悬空，**规格书禁止**。

**U-Boot 冷切换脚本（已核对 mainline v2025.01 源码）**
- ⚠ **`gpio status <pin>` 不可用于脚本**：`do_gpio_status()` 只 printf，**不设环境变量**。
- ✅ 正确语法：**`gpio read <varname> <gpiopin>`** → `cmd/gpio.c` 中 `env_set_ulong(str_var, value)`。
  需 `CONFIG_CMD_GPIO_READ`（若未开则报 Unknown command 'read'，退回手动切 DTB）。
- U-Boot 无 `MESON_GPIO_A_0` 之类编译期常量（只有 `meson-a1-gpio.h`），GPIO 号由运行时 `gpio-ranges` 算出 → **不能用 `gpio get 2` 固定编号**，须用名字 `FUSB340_SEL`（gpio-hog 的 line-name）或 bank 写法 `A_2`。
- 内核 `pinctrl-meson-g12a.c` bank 顺序：**Z(0-15) → H(16-24) → BOOT(25-40) → C(41-48) → A(49-64) → X**（GPIOA_2 ≈ 51，但跨内核/U-Boot 不保证一致，不硬编码）。

**CI 双 job 设计**

- **`kernel`**（`runs-on: [self-hosted, ARM64]`）：完整 `./compile.sh kernel BOARD=halo-a311d BRANCH=current`。**GitHub 官方 runner 只有 x86，需自托管 ARM64**；用 QEMU 模拟会很慢。
