# MAIN_V0.3 — PCIe / USB3.0 冷切换使用说明

## 文件清单

| 文件 | 说明 |
|------|------|
| `meson-althaea-a311d.dts` | USB3.0 模式（默认）→ 产出 `meson-althaea-usb3.dtb` |
| `meson-althaea-pcie.dts` | PCIe 模式 → 产出 `meson-althaea-pcie.dtb` |
| `althaea-mode.hush` | U-Boot 脚本：读 SEL 电平，自动选 DTB |

---

## 硬件前提：R85 / R87 二选一跳线

```
GPIOA_2 ──┬── R86(0Ω) ──→ FUSB340 .6(SEL)
          ├── R87(4.7k) ──→ A_3V3    ← 上拉
          └── R85(4.7k) ──→ GND      ← 下拉
```

| 贴装 | SEL 上电电平 | 模式 | 对应 DTB |
|------|-------------|------|----------|
| **R85**（下拉，默认） | LOW | **USB3.0** | `meson-althaea-usb3.dtb` |
| **R87**（上拉） | HIGH | **PCIe** | `meson-althaea-pcie.dtb` |

**必须二选一，不能都不贴** —— FUSB340 规格书明确：
> *"The control inputs must be held HIGH or LOW; they must not float."*

两颗都贴则 3.3V 被 4.7k//4.7k 分压成 1.65V，属**未定义电平**，禁止。

---

## 一、编译两个 DTB

在mainline 内核树中：

```bash
# 把两个 dts 放到内核源码
cp meson-althaea-a311d.dts \
   meson-althaea-pcie.dts \
   <kernel>/arch/arm64/boot/dts/amlogic/

# 在 Makefile 的 dtb-y 末尾追加
echo "dtb-$(CONFIG_ARCH_MESON) += meson-althaea-usb3.dtb" >> <kernel>/arch/arm64/boot/dts/amlogic/Makefile
echo "dtb-$(CONFIG_ARCH_MESON) += meson-althaea-pcie.dtb" >> <kernel>/arch/arm64/boot/dts/amlogic/Makefile

cd <kernel>
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- dtbs
```

产物：
```
arch/arm64/boot/dts/amlogic/meson-althaea-usb3.dtb
arch/arm64/boot/dts/amlogic/meson-althaea-pcie.dtb
```

## 二、部署到板子

```bash
cp meson-althaea-usb3.dtb meson-althaea-pcie.dtb /boot/
cp althea-mode.hush              /boot/
```

## 三、接入 U-Boot 启动流程

在 `/boot/extlinux/extlinux.conf` 或 U-Boot 的 `bootcmd` 中，
**在 bootm 之前**调用脚本：

```
echo "=== Althea A311D mode select ==="
source /boot/althaea-mode.hush
```

脚本会把选好的 dtb 路径写入环境变量 `${fdt}`，之后 `bootm` 自动使用。

### 手动验证（先在 U-Boot 提示符试）

```
=> source /boot/althaea-mode.hush
SEL=LOW  -> USB3.0
DT = /boot/meson-althaea-usb3.dtb
=> bootm ${kernel_addr_r} ${ramdisk_addr_r} ${fdt_addr_r}
```

## 四、语法依据（已核对U-Boot v2025.01 源码）

| 用法 | 源码位置 | 说明 |
|------|---------|------|
| `gpio read <var> <pin>` | `cmd/gpio.c` → `env_set_ulong(str_var, value)` | 值写入环境变量 |
| `gpio status <pin>` | `do_gpio_status()` | **只打印，不设变量**，脚本里不可用 |

> ⚠ `gpio read` 需要 `CONFIG_CMD_GPIO_READ`。若 U-Boot 未开启该选项，
> 会报 `Unknown command 'read'`，此时退回**手动切换**：
> ```
> => setenv fdt /boot/meson-althaea-pcie.dtb
> => bootm ${kernel_addr_r} ${ramdisk_addr_r} ${fdt_addr_r}
> ```

## 五、常见问题

| 现象 | 原因与处理 |
|------|-----------|
| `GPIO: 'FUSB340_SEL' not found` | U-Boot DT 里没有该 `line-name`。改为 bank 写法：`gpio read althea_sel A_2`，或在 U-Boot 的 dtsi 里给该脚加 `line-name = "FUSB340_SEL"` |
| `Unknown command 'read'` | U-Boot 未开 `CONFIG_CMD_GPIO_READ`，用手动切 DTB |
| 切了 PCIe 但 M.2 不通 | ① 确认跳线贴的是 R87；② 确认 `meson-althaea-pcie.dtb` 已在用；③ 查 `dmesg \| grep -i pcie` |
| M.2 识别不到 | `dmesg \| grep -i pcie`：若看不到 link，先量 FUSB340 的 SEL 是否真为 HIGH |

## 六、设计说明：为什么不能运行期热切

A311D 的 PCIe 与 USB3 共用同一个 combo PHY（`usb3_pcie_phy`, phy@46000）：

```dts
/* meson-g12-common.dtsi:164  */
&pcie { phys = <&usb3_pcie_phy PHY_TYPE_PCIE>; };
/* meson-g12-common.dtsi:2510 */
&usb  { phys = <&usb3_pcie_phy PHY_TYPE_USB3>; };
```

PHY 的 `#phy-cells = <1>`，调用方用`PHY_TYPE_PCIE` / `PHY_TYPE_USB3` 区分模式。
**DTS 是编译期静态描述**，PHY 归属在编译时已定死。运行中改 FUSB340 的 SEL
只能改变物理通断，SoC 内部仍按 dtb 写死的那一侧枚举设备 → 两侧不一致，失效。

故采用**冷切换**：重启时选 DTB，每次都是全新 probe，干净可靠。
