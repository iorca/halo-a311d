# MAIN_V0.3 — PCIe / USB3.0 冷切换使用说明

> 2026-10-21 按「SEL 是硬件 strap」重审并订正全文。
> 旧版本里「u-boot 拉高 SEL」的方向是错的，且文件名 / 接入方式 / GPIO 写法都已过时。

## 硬件：R85 / R87 选贴，决定 SEL 电平

```
GPIOA_2 ──┬── R86(0Ω)  ──→ FUSB340 .6(SEL)
          ├── R87(4.7k) ──→ A_3V3   ← 上拉（贴这个 = PCIe）
          └── R85(4.7k) ──→ GND     ← 下拉（贴这个 = USB3.0，默认）
```

| 贴装 | SEL 上电电平 | 模式 | 启动的 DTB |
|------|-------------|------|-----------|
| **R85**（下拉，默认） | LOW | **USB3.0** | `amlogic/meson-halo-a311d.dtb` |
| **R87**（上拉） | HIGH | **PCIe** | `amlogic/meson-halo-a311d-pcie.dtb` |

FUSB340 规格书：*"The control inputs must be held HIGH or LOW; they must not float."*
→ **必须二选一，不能都不贴**；两颗都贴则 3.3V 被 4.7k//4.7k 分压成 1.65V，属未定义电平，禁止。

**SEL 由电阻决定，SoC 不许驱动。** 两个 dts 变体的 `fusb340_hog` 因此
**不能写 `output-low` / `output-high`** —— SoC 一强驱就把 strap 电平盖掉，
`gpio read` 读到的就永远是 SoC 自己的输出值。不写 `output-*` 时 hog 是 input，只占位。

## 软件链路（armbian 实际走的，不是 extlinux）

```
boot/boot-meson64.cmd
  └→ 部署为 userpatches/bootscripts/boot-meson64.cmd   （armbian 优先用这份覆盖自己的）
       └→ armbian-bsp-cli postinst 用 mkimage 编成 /boot/boot.scr
            └→ u-boot 执行 boot.scr
                 ├─ load /boot/armbianEnv.txt + env import -t   （boot.cmd:96-98）
                 ├─ 我们的注入块：gpio read → setenv fdtfile
                 └─ load ... dtb/${fdtfile}                      （boot.cmd:124/148）
```

判定依据（`lib/functions/rootfs/distro-agnostic.sh:190-195`）：armbian 先从
`$USERPATCHES_PATH/bootscripts/<BOOTSCRIPT 源名>` 找，命中就用它。本板源名 = `boot-meson64.cmd`。

**不是 extlinux**（`SRC_EXTLINUX` 没开），所以旧文档里「写 extlinux.conf」那条不适用。
`boot/althaea-mode.hush` 只是**可读参考**，u-boot 不会主动 source 它。

## 关键：GPIO 必须用数字编号 51，符号名无效

`gpio read althea_sel 51`

> ⚠⚠ **不要写 `GPIOA_2` / `A_2` / `FUSB340_SEL`** —— 在 meson 上都解析不了，
> 只会打印 `GPIO: 'x' not found`，然后变量为空 → 静默兜底 USB3.0，PCIe 永远选不上。

推导（u-boot 2026.04 源码核对）：

| 环节 | 位置 | 结论 |
|---|---|---|
| bank 名来源 | `drivers/pinctrl/meson/pinctrl-meson.c:334` | `uc_priv->bank_name = priv->data->name` → `"periphs-banks"` / `"aobus-banks"` |
| 前缀匹配 | `drivers/gpio/gpio-uclass.c:176` | `"GPIOA_2"` vs `"periphs-banks"` 不匹配 → 符号名死路 |
| 标签查找 | `gpio-uclass.c:128-143` | 只匹配**已被 request** 的引脚，用不上 |
| 数字路径 | `gpio-uclass.c:160` | `offset = numeric - gpio_base` |
| base 分配 | `gpio-uclass.c:1413` | 按探测顺序累加；periphs 节点在 `meson-g12-common.dtsi:271`、aobus 在 `:1759` → **periphs 先，base=0** |
| bank 顺序 | `pinctrl-meson-g12a.c:1205-1212` | Z(0-15) H(16-24) BOOT(25-40) C(41-48) **A(49-64)** X(65-84)，num_pins=85，pin_base=EE_OFF=15 |

→ GPIOA_2 在 periphs 内偏移 = 49 + 2 = **51**；全局 gpio 编号 = 0 + 51 = **51**。

**若上机发现「贴了上拉却读到 LOW」**，先怀疑编号：在 `/boot/armbianEnv.txt` 加
`althea_sel_num=66`（= 51 + EE_OFF，即 Linux 侧编号，对应 AO 先探测的排布），重启再看。

## 依赖的两个 CONFIG

- `CONFIG_CMD_GPIO` —— 有 gpio 命令
- `CONFIG_CMD_GPIO_READ` —— 才有 `gpio read <var> <pin>`
  （`cmd/gpio.c:279-280`：先 `gpio_direction_input()`，再 `env_set_ulong(var, 0|1)`）

两个都在 `config/boards/halo-a311d.conf` 的 `post_config_uboot_target__extra_configs_for_halo_a311d()` 里打开。

## 上机验证

串口开机看这几行（我们脚本打的）：

```
althea: SEL(gpio 51 = GPIOA_2) = 1
althea: SEL=HIGH -> PCIe
althea: fdtfile=amlogic/meson-halo-a311d-pcie.dtb
```

然后 `cat /proc/device-tree/model` 与 `dmesg | grep -i pcie` 交叉确认。

| 现象 | 排查 |
|---|---|
| `GPIO: '51' not found` | 编号不对 → 试 `althea_sel_num=66` |
| `Unknown command 'read'` | 缺 `CONFIG_CMD_GPIO_READ` |
| 打印 `cannot read ... failed` | 同上，或引脚被别的驱动占用（EBUSY 只打印，仍会读） |
| 贴了上拉却读到 LOW | ① 编号不对；② dts 里 `fusb340_hog` 还在写 `output-*`；③ 量 FUSB340 SEL 实际电压 |
| 切了 PCIe 但 M.2 不通 | 确认贴的是 R87 + boot 的是 `-pcie.dtb` + `dmesg \| grep -i pcie` |

`althea_mode=pcie|usb3`（armbianEnv.txt）可**强制**选 dtb，但改不了 mux ——
mux 由电阻决定。强制错配 = PCIe 配置的内核跑在 USB3 接线上。

## 为什么不能运行期热切

`&pcie` 与 `&usb` 共用 `usb3_pcie_phy`（`meson-g12-common.dtsi:164 / 2510`），
`#phy-cells = <1>`，靠 `PHY_TYPE_PCIE` / `PHY_TYPE_USB3` 区分。
**DTS 是编译期静态描述，PHY 归属编译时就定死**；运行期改 SEL 只能改物理通路，
SoC 内部仍按 dtb 写死的那一侧枚举 → 两侧不一致，失效。所以只能冷切换：重启时选 DTB。
